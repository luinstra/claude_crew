# Engine-owned measure-twice protocol

This is the source implementation contract. The required Claude Code CLI
lifecycle cases and their limits are recorded in
[Phase 4 evidence](phase-4-measure-twice-evidence.md).
Build uses [its engine-owned protocol](build-protocol.md) and existing executor
routes. Both loops compose owner-bound reviews; standalone review/debate keep
their own pointers.

## Claude Code native result boundary

Claude Code 2.1.287 exposes a native launch handle (`agentId`) and an owned
`output_file` JSONL transcript. The adapter must first observe an actual owned
hand-back or completion notification. File existence, length, a final JSONL
record or elapsed time never establishes completion. A `SubagentHandback`
delivers the completed report immediately; a later notice that it was already
delivered must not induce another wait/parent turn.

Issued native advisor/reviewer work adds `commands.native_bind` and
`commands.native_capture`. After the actual Agent launch, append its observed
`--handle` and `--output-file` to bind once. The launch prompt must be exactly
`Read <issued prompt_path> and perform exactly the issued action.` After actual
completion, invoke capture with the same fields and `--completion-observed`.
The capture flag attests a host event; it is never generated by artifact probing.

`multiagent/claude_native_transport.py` binds the existing claimed owner/action,
prompt bytes, observed handle and path in a write-once transport receipt. It
accepts only the demonstrated CLI version/shape: matching handle/session/project
on every record, the exact initial prompt reference, and one nonblank assistant
`SubagentHandback.input.message` string. The demonstrated public task alias is
accepted only when it targets the exact home-project/session/handle transcript;
foreign aliases and linked parent directories refuse, as do foreign
prompts/handles/owners, incomplete JSONL, ambiguous reports and unsupported
versions/shapes. Direct capture is admitted only for **2.1.287**, not a minimum
version range. Other versions retain the issued scribe/host-Write fallback until
their actual public result surface has been validated.
The exact UTF-8 message bytes, including CRLF, Unicode and presence/absence of a
final LF, are retained in a transport artifact and submitted through the existing
capture/guard/receipt APIs. Successful replay uses retained bytes and the existing
accepted digest, so host cleanup does not require another paid task.

Keep the CLI process alive until owned background commands actually complete.
Ending a `--print` process can kill a background external review. For a retry
with only one pending external action, its issued execute command may run in the
foreground. A killed owned command is recoverable only after its actual host
termination is confirmed; successful reviewers remain accepted.

This opt-in boundary does not launch work, decide judgments, infer completion,
or add providers/capabilities. Receipts do not replace LoopState/workflow state.
Model pins and review attribution remain those of the issued action; direct code
capture invokes zero scribes. Parent synthesis and unsupported native surfaces
keep the existing transport. The scribe/host-Write fallback remains available,
with explicit EOF guidance and an audit requirement before claiming fidelity.
Role authoring instructions remain advisory; an advisor's Bash write is not
mechanically confined by this result transport.

## Requests and requirements

The public Python entry is `start_measure_twice(MeasureRequest)`;
`MeasureRequest(raw_arguments: str, session_id: str,
requirements: CapturedRequirements | None = None)` preserves raw user text.
`CapturedRequirements(question_id: str, answers: tuple[str, ...])` has exactly
three nonblank answers in the issued order. The CLI reads this exact UTF-8 JSON
shape, with no extra fields and integer `schema=1`:

```json
{"schema":1,"raw_arguments":"--panel quick describe a feature","requirements":null}
```

Call `crew measure-twice -f <spill> --session-id <literal-id> --consume`.
`--consume` deletes the spill only after a successful response; errors retain it.
It cannot consume the selected source document or live state file. Use a new
spill under `.crew/requests/`, and keep user text off shell command lines.

The lexical grammar is:

- Zero or more leading `--panel <value>` and `--seats <value>` pairs, each at
  most once; values are a single plain or quoted token. Equals syntax, unknown
  leading flags and missing/duplicate values are errors. If both are present,
  the existing seat resolver gives explicit seats precedence. Absent panel
  selection uses configuration and the existing resolver; it never inserts full.
- After flag separator whitespace, the remaining text is the task. Without
  flags, raw task whitespace is preserved. Embedded flags and document mentions
  remain task data. No command substitution or environment expansion occurs.
- POSIX shell tokenization is used ONLY to recognize an exact document source:
  the whole task must tokenize to one token ending in case-sensitive `.md`.
  `requirements.md` and `"design with spaces.md"` are documents;
  `implement according to design.md please` is task text. Two or more tokens
  all ending in `.md` are competing explicit sources and refuse. A multiword
  unquoted path is task text; quote it to select the document.
- Relative paths anchor to `crew_base()` (project root), independently of process
  cwd. Documents must be readable, nonblank UTF-8. Missing, directory, unreadable,
  empty and invalid UTF-8 sources return `requirements_source_unreadable` naming
  the path and reason, before activation. Source bytes, including line endings,
  are frozen and SHA-256 bound. Documents skip the interview.

Task mode returns a pure code-rendered ordered interview without creating state:

| Stable question key | Question |
|---|---|
| scope | What should the plan accomplish, and what is outside its scope? |
| constraints | Which constraints, existing behavior, and design decisions must it preserve? |
| acceptance | What observable checks will establish that the work is complete? |

The question identity hashes raw request bytes and the ordered keys/text. Resubmit
with the exact returned `question_id` and ordered answers:

```json
{"schema":1,"raw_arguments":"--panel quick describe a feature","requirements":{"question_id":"<issued full SHA-256>","answers":["scope answer","constraints answer","acceptance answer"]}}
```

Document plus answers, wrong identity/order/cardinality, or competing sources
refuse. An identical active request resumes; a different request/source digest
cannot replace its lifetime, budget or binding. An identical inactive request replays its terminal status. A different immutable
request starts a fresh lifetime after normal approval, cancellation or terminal
review failure. Safety-force-exited lifetimes remain terminal for every request. The engine never calls compatibility `state init --force`.

## State and review ownership

The public domain request types are dataclasses in `multiagent/measure_twice.py`:

| Type | Fields |
|---|---|
| MeasureRef | `session_segment: str`, `loop_instance_id: str`; JSON adds integer `schema=1` |
| MeasureResult | `ref: MeasureRef`, `action_id: str`, `status: ok|failed|timeout|cancelled`, `plan_sha256: str|null`, `returned_sha256: str`, `diagnostic: str|null` |
| MeasureSubmission | `result: MeasureResult` |
| MeasureRecovery | `ref: MeasureRef`, `action_id: str`, `confirmation: str` (exact `not_running`) |
| MeasureDecision | `ref: MeasureRef`, `question_id: str`, `kind: str`; optional `confirmation`, `retained_phase`, `retained_run_id`, `completed_action`, `plan_sha256`, `requirements: CapturedRequirements` |

Result digests are full lowercase SHA-256; successful advisor results require
`plan_sha256`. The result JSON has exactly those six fields, including nullable
`diagnostic`, and the exact schema-1 `ref`. `measure-twice-submit -f` reads this
result shape; normal hosts use the deterministic capture helper instead of
constructing it. Python callers supply MeasureSubmission to the typed API.
Both verify the claimed owner/action and staged digest under the loop lock.

`MeasureRef` is the exact schema-1 session segment and loop-instance identity.
`MeasureStep` returns `needs_input`, `work_batch`, `waiting` or `terminal`.
`measure-twice-next`, `-claim`, `-submit`, `-capture`, `-recover`, `-decide` and
`-cancel` accept the issued owner; `measure-twice-resume --session-id` discovers
that lifetime or adopts legacy state. WorkItems include literal command strings
with quoted argv, frozen roles/models/routes, prompt and ingress paths. Hosts
must not select paths, re-resolve pins or advance from a review-local response.

LoopState schema 5 carries optional `mt_workflow` (added in schema 4) and
`bl_workflow` (added in schema 5). The planning journal stores progress and
receipts, not duplicate budgets. Preparation checkpoints the full roster,
routes, target bytes and identity before run filesystem creation. Loop review
identity adds `kind=loop_review` plus session/loop/lifetime/generation binding.
No standalone or legacy review pointer is read or written to advance mt.
Shared review action verbs validate the active owner; `review-next` refuses this
kind. Retry receipts reconcile a durable new attempt before loop advancement.

Locks always order loop state before review run. Provider/model work is outside
locks. Transactions preserve unrelated hook counters and unknown state keys.
`state set`, `begin-review` and `record-verdict` refuse current engine-owned
build and measure-twice journals, preventing a second certification path. Lock failures
are typed errors with no partial state. On platforms without `fcntl`, existing
state locking degrades with a diagnostic; concurrent-write guarantees are not
claimed there.

`ReviewEvidence` is the sole shared verdict-guard input. `LegacyReviewSource`
carries the manifest identity and observed pointer. A missing legacy manifest
has a null digest and zero usable seats, retaining the existing failure/advisory
behavior. `LoopReviewSource` carries the exact binding/ReviewRef and a full
accepted-outcome digest derived from verified accepted action bytes and judgment.
`BindingStatus.MATCH` means matching legacy pointer or matching loop ownership;
`DIVERGED`/`MISSING` describe legacy pointer observations. Mutable pointers never
certify loop evidence. The guard preserves strict majority, all-failed symmetry,
target drift checks, revision counts, advisory collection and forced audit stamps.

Advisor actions are fresh, with no build executor continuation. Static Claude, Codex and
OpenHands host-role metadata admit planning (`crew:advisor`, `inherit`, advisory
access). Codex uses the shared role prompt and owned host-written capture through
the [Codex transport](codex-transport.md). OpenHands uses frozen backend context and
persisted native task events through the [OpenHands transport](openhands-transport.md). Cursor and unknown hosts fail with
`unsupported_planning_host` before new activation. The stage machine is
host-neutral.

Each action writes its own staging plan. Successful capture seals those bytes,
checkpoints promotion, then writes an immutable canonical `plan-N.md` in the
lifetime namespace. That canonical path is `plan_file` and the review target.
Late staging writes cannot replace it. Replays require identical receipts;
recovery of a lost claim requires explicit `not_running`, never elapsed time.
Terminal responses name the lifetime plan directory for attended cleanup; plans
and evidence are not automatically deleted. Active bound and pending review
references protect run directories without pointers.

## Human decisions and transport

Bound questions require exact owner and `question_id`. Completion advisories
carry named conditions plus the exact accepted `outcome_sha256`. A human retry
of a drifted target creates a fresh generation over current readable bytes; an
unreadable current target parks for explicit planning recovery. Partial-panel
retry retains successful reviewers and reissues only missing/failed seats. Decisions use
`measure-twice-decide --session-segment <issued> --loop-instance-id <issued>
--question-id <issued> --kind <decision>`:

| Question | Decision |
|---|---|
| completion_advisory | `force --confirmation force`, `retry_review`, or `cancel` |
| synthesis_retry | `retry_synthesis` or `cancel` |
| advisor_retry / legacy_plan_recovery / plan_recovery | `retry_advisor` or `cancel` |
| rising_findings | `continue` or `cancel` |
| legacy_requirements | `requirements --answers-file <ordered JSON array>`, `retry_requirements` after repairing the source, or `cancel` |
| legacy_work_not_running | same kind with `--confirmation not_running --retained-phase <issued> --retained-run-id <issued>` |

Legacy active drafting AND reviewing first park for quiescence. Neither absent
nor partial/finished-looking files prove old work stopped. Preserve budgets and
prior verdicts. After confirmation, readable documents or nonblank preserved
task text establish minimum readiness. Prior REVISE/REJECT requires retained
plan and verified old panel; missing context parks. An explicit completion
attestation (`--completed-action initial_plan|revision|replan --plan-sha256`)
may adopt matching already-produced bytes without another advisor. Legacy done
only finalizes. Resuming cancelled/force-exited loops returns terminal status; only a different
request after normal completion/cancellation admits a fresh lifetime.

Synthesis failure parks and is never an all-failed panel. Explicit synthesis-only
retry creates a new attempt retaining every successful reviewer; the underlying
shared CLI spelling is `review-retry --synthesis-only`. First truly all-failed
panel creates a fresh generation; the second consecutive one ends `review_failed`.
A blocking verdict requests structural revision/replanning. The synthesis counts
distinct blocking causes; growth after a prior positive count warns the human. If a synthesis omits the
count, no growth claim is made.

Without the demonstrated direct boundary, Claude Markdown needs actual Task
RESULT text transported by its issued scribe, with a distinct host-Write fallback. A partial file never proves a
successful return. Advisor completion reports use parent Write (no extra scribe); all captures
accept only issued paths.
Helpers hash, construct exact envelopes, submit and retain receipts; they print
metadata only. Parent synthesis provides its judgment using `--verdict` and
`--minor-only`; reviewers/formatters never supply a synthesis judgment.

The injected `NativeRuntime` consumes frozen work: `launch`, notification-driven
`completions`, optional `cancel`. Its runner launches independent native work in waves, captures returned bytes
directly and asks for zero scribes. Codex-native batches, including a single action, require an explicit
`max_concurrency` based on currently available host slots. Each wave consumes
completion notifications before another starts; incomplete waves return with
their owned handles and leave later seats unclaimed. Other hosts retain the
whole-batch default unless the caller supplies a limit. It does not register hosts, change route admission or
execute external reviewers through a native route. Production external actions
keep `review-execute`, launched before native waits by the command adapter.

## Revision safety clarifications

Review preparation and provider availability/timeout probes run outside owner
and review locks. The engine revalidates current owner, bounds and frozen action
before checkpointing preparation or committing a claim; cancellation during a
probe prevents a paid launch. A pending bind uses `LoopReviewSource` without an
accepted-outcome digest. Verdict application requires the full accepted digest.

Every failed synthesis attempt issues a new question identity bound to its
review attempt. `synthesis_retry` accepts `retry_synthesis`; `completion_advisory`
accepts `retry_review`. A consumed decision never authorizes a later paid retry.
Cancellation remains available after bounds expire; explicit force still checks
bounds under the owner lock. Already-recorded done state only finalizes.

An actually completed advisor with a missing, unreadable, empty or invalid UTF-8
staged plan settles as a failed action and issues `advisor_retry`. Exact returned
bytes and the observed result are retained in a durable transport receipt;
repairing staging cannot change a replay. A file's state never proves completion.
Legacy recovery accepts an absent loop discriminator, waits for confirmed
quiescence, then returns through the same retained-plan/REVISE/REJECT logic after
requirements recovery. Budgets and prior-feedback validation remain intact.
